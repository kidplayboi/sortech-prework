# D2 빌드노트 — 슬라이스별 설계 결정

> 슬라이스 순서: ① L4 렌더링 → ② deploy 집중 모드 → ③ 정적 상태보드 → ④ L5 보안 축 → 게이트 → 녹화

## 슬라이스 ① L4 렌더링 — "취소 불가 in-flight 작업" 정리 경로 선설계 (게이트 carryover 이행)

트리클 사가(9~12차)의 교훈 = L1~L3의 소켓 읽기는 **취소 불가능한 블로킹**이라 데몬 스레드 + 소켓 shutdown 위임이라는 우회가 필요했고, 그 우회가 4라운드에 걸쳐 벗겨졌다. L4는 같은 함정에 들어가지 않도록 **구조가 다른 도구를 다르게 다룬다**:

| 축 | L1~L3 (_bounded_get) | L4 (render.py) |
|----|---------------------|----------------|
| 블로킹 단위 | 소켓 read (취소 불가) | Playwright 작업 (자체 타임아웃 = **취소 가능**) |
| 시한 강제 | 데몬 워커 + join + shutdown 위임 | goto/wait 타임아웃 + try/finally `browser.close()` |
| 최악 시나리오 | 락에 갇힌 스레드 (프로세스 내 회수 불가 변종 존재) | 브라우저 = **별도 OS 프로세스** — close 실패해도 프로세스 kill로 회수 가능, 스레드 락 클래스 원천 부재 |
| 상주 여부 | 요청마다 새 커넥션 | **체크마다 launch/close** — 상주 브라우저는 크래시 누적·좀비 위험, L4는 저빈도라 launch 비용(수백 ms) 수용 |

판정 규칙 (spec L4 = "JS 콘솔 에러·핵심 요소 존재"):
- 페이지 로드 실패/타임아웃 → **FAIL**
- pageerror(잡히지 않은 JS 예외) ≥ 1 → **FAIL** (첫 에러를 detail에 — 알림 예: "TypeError: cart is undefined")
- 렌더된 본문에서 마커 부재 → **FAIL** (원본 HTML엔 없고 JS가 그리는 SPA 커버 — L2와의 차별점)
- console.error만 있는 경우 → **WARN** (서드파티 스크립트·광고가 흔히 유발 — 오탐으로 🔴 신뢰를 깎지 않는다)

운영 규칙:
- **opt-in**: 사이트 설정 `render: true`일 때만 (무겁고 Playwright 의존 — 기본 off)
- Playwright 미설치 + render:true → **조용한 통과 금지**(noop=실패 은폐 클래스) — "L4 검증 불가" WARN + 설치 안내
- `watch`는 N패스마다 1회(`--render-every`, 기본 5 — 평시 L1~L2 위주라는 스펙 트리거 설계), `once`/`status`는 매번, deploy 모드(슬라이스 ②)는 매 체크
- settle: `wait_until="load"` + 1초 고정 대기 후 판정. 렌더가 더 느린 SPA는 한계로 문서화 (기다림 휴리스틱을 쌓는 것보다 정직한 경계가 낫다)

## 슬라이스 ② 배포 집중 모드 — 앵커 계약이 핵심

`watcher deploy <site>`는 평시 순찰(상태 전이 엔진·state.json)과 **분리된 일회성 판정 세션**이다. 상태를 읽지도 쓰지도 않고, 시작·결과를 각 1회 반드시 통보한다(무소식 없음).

**기대 버전 앵커** (D1 게이트 기각-2에서 D2로 승계된 계약): `--expect-version` 없이 "원본==사용자"만 보면, **배포가 서버에 아예 닿지 않아 둘 다 옛 버전**인 상태를 "일치=정상"으로 오판한다. 앵커가 있으면 원본·사용자 모두 그 값이어야 안정이며, 원본부터 다르면 "배포가 서버에 반영되지 않음"으로 구분해 보고한다. 앵커 없이 쓰면 시작 알림에 그 한계를 명시한다.

`--expect "문구"` = 서버를 만질 수 없는 빌더형(아임웹 등) 블랙박스용. 원문에서 찾고, `render:true`면 렌더된 화면에서도 찾는다. 렌더 확인 불가(미설치·실패)는 "미출현"이 아니라 pending으로 다룬다.

미반영(pending) 통보는 **사유가 바뀔 때만** — 같은 사유를 15초마다 재통보하면 알림 피로로 무시당한다. 안정 판정은 깨끗한 통과만 카운트(warn은 실패도, 안정도 아님).

## 슬라이스 ③ 정적 상태보드

회의 확정대로 서버 없음 — `watch`/`once`가 매 패스 `board.html`을 원자적으로 재생성(tmp+replace), `meta refresh` 15초. 최근 알림 이력은 `board_history.json` 20건. 두 파일 모두 gitignore(실행 산출물).

- **모든 동적 텍스트 `html.escape`** — 마커·에러 문구는 감시 대상 사이트의 응답에서 유래한다. 이스케이프 없이 보드에 박으면 감시 대상이 보드 안에서 마크업을 실행시킬 수 있다(회귀 테스트로 고정)
- 보드 생성 실패는 **격리 후 경고만** — 보드가 감시를 죽이면 안 된다(가용성 우선)
- `status`는 읽기 전용 계약이라 보드도 쓰지 않는다

## 슬라이스 ④ L5 보안 축 — 클로킹 + 평판

근거·경계 = `03-보안축-리서치.md`. `security: true` opt-in.

**클로킹**: 같은 URL을 일반 UA와 검색봇 UA(+검색 유입 referer)로 두 번 읽어 비교. 판정 등급을 오탐 비용 기준으로 나눴다 —
- 봇 시점에만 스팸 문구 → **FAIL** (침해 의심)
- 양쪽 모두에 스팸 문구 → **통과** (사이트 자체 성격일 뿐 클로킹 아님)
- 봇 시점에서 이 사이트 마커가 사라짐 → **WARN** (봇 차단 WAF일 수도 있어 단정하지 않음)

L1~L3의 굳은 fetch(`_bounded_get`)를 UA·Referer 파라미터만 추가해 재사용했다 — 두 번째 fetch 경로를 새로 만들면 트리클 사가에서 얻은 방어(총 시한·크기 상한·워커 회수)를 잃는다.

**평판 = Google Safe Browsing.** ⚠️리서치는 "v5로 구현" 권고였지만 **실측으로 뒤집었다**: v5 `hashes:search`는 protobuf만 반환하고 JSON 요청(`$alt=json`)이 400으로 거부된다(실측). protobuf 의존 추가나 수동 파싱은 이 스코프에 과하다 → **v4 `threatMatches:find`(JSON) 채택**. v4 종료 예정일 2027-03-31이며, 이관은 `check_reputation` 한 함수만 바꾸면 된다. 키 미설정은 조용한 통과가 아니라 WARN(noop이 실패를 성공처럼 보고하는 클래스 차단).

**녹화용 클로킹 재현 서버** `demo/cloaked_site.py`: 감시 대상 데모(GitHub Pages)는 정적이라 UA 분기가 불가능하다. 클로킹은 서버가 요청자를 보고 응답을 가르는 현상이므로 동적 엔드포인트가 필요 — 외부 계정 없이 평가자가 재현할 수 있게 로컬 서버로 뒀다(데모 대상 선정 근거의 "평가자 재현 가능"과 동일 기준).
