# 회고 노트 (실시간 축적)

> 제출물 2번(회고)의 원재료. 진행하면서 그때그때 쌓고, 마지막에 S2a~S2d 구조로 정제한다.
> S2a 도구·순서 / S2b 막힌 지점과 돌파 / S2c 틀린 답 대응 / S2d 다시 한다면

## 2026-07-29 — 과제 분석 · 레포 세팅

- 시작을 코딩이 아니라 **과제 문서 전수 분석**으로 잡았다. 요구사항을 ID(T/S/E/A)로 추출해 추적 가능하게 만들고, 제출 직전 전 항목 대조하는 구조.
- docx를 눈으로만 읽지 않고 XML 레벨로 파싱해 숨은 콘텐츠(변경추적·주석·숨김텍스트)까지 검증 — "놓치는 게 없어야 한다"는 요구를 도구로 해결.
- 기록을 사후 작성하면 오답 순간(S1c)이 유실된다 → 실시간 아카이빙 프로토콜을 먼저 세우고 빌드는 그 다음.
