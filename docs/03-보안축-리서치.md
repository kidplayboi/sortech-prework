# 보안·무결성 축(가칭 L5) 리서치 — 무설치 원칙과의 정합성 검증

> 2026-07-30. 배경: 사토시가 "감지 외에 한 축 더 — 트래픽으로 인젝션 감지?"를 제안 →
> AI가 "트래픽 관찰은 설치형이라 무설치 포지셔닝과 모순, 대신 '페이지에 드러난 침해 흔적'
> 관찰은 성립"으로 교정 → 감으로 확정하지 않고 리서치로 검증 (AI 웹리서치 에이전트, 한/영 교차).

## 종합 판정: 추가할 가치 있음

1. **카테고리 실재** — 외부 관찰 전용 보안 감시는 실제 시장: Reflectiz(무설치 외부 크롤, 2025-10 $22M 시리즈B), Sucuri SiteCheck(무료 원격 스캐너), c/side($99/월~, 이쪽은 태그 설치형). 무설치만으로 상업 제품이 성립한다는 존재 증명.
2. **한국 서사 실증** — 해킹된 중소 사이트에 도박 스팸을 심고 **검색봇에게만 보여주는(클로킹)** 수법이 국내 실무 블로그·복구 사례로 실증. 웹쉘 심긴 뒤 3개월 만에 발견한 쇼핑몰 사례, Sucuri 통계로 정화 사이트의 20.3%가 SEO 스팸. KISA가 반기별 「악성코드 은닉사이트 탐지 동향」을 낼 만큼 국가 단위 상시 이슈 — 단 KISA 점검은 일회성이라 "상시 감시 공백"이 우리 자리.
3. **무설치 원칙과 정합** — 후보 신호 전부 읽기 전용 HTTP 관찰로 성립.

## 하지 말 것 (정직한 경계 — 문서·회고에 그대로 박제)

- 서버 내부 파일 변조·웹쉘·DB 악성코드·**인젝션 시도 탐지를 약속하지 말 것** — 공격 시도는 서버 로그에만 존재, 외부 관찰자는 자기가 유발한 응답만 본다 (Sucuri 공식 문서가 자기 원격 스캐너의 한계로 명시하는 지점과 동일)
- Magecart "완전 탐지" 주장 금지 — 세션/지역 타깃 스키머는 외부 스캔을 회피 (설치형 c/side가 존재하는 이유)
- **rDNS 검증형 클로킹은 못 잡음** — 정교한 클로커는 UA가 아니라 진짜 검색봇 IP를 역방향 DNS로 검증. 우리가 잡는 건 "저가형·대량 살포형(UA/referer 분기)" — 이 한계를 스코프로 명시하는 것 자체가 설계 판단
- 스크립트 해시 단위 감시 금지 (CDN 정기 갱신 = 오탐 홍수)

## 확인 불가로 남긴 것 (과장 금지)

KISA "웹체크" 상시 서비스 실체 · Reflectiz/Sucuri 유료 정확 가격 · GSB 테스트 URL(testsafebrowsing.appspot.com)의 현재 동작 — 사용 전 실측 필요 · "감염→발견 평균 197일" 통계의 원출처(벤더 블로그 인용이라 참고용).
