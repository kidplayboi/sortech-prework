# 2026-07-30 세션 15 — "깊이가 부족하다" 문답 → 보안 축 리서치

**도구**: Claude Code (Claude Fable 5) + 웹리서치 에이전트 (한/영 교차 검색)

## 프롬프트 → AI 답변 → 나의 대응

**나**: "주제가 참 애매하긴 하네" → "고객사마다 어떻게 이식할 건데? 상품화되면?" → "아직 깊다는 생각이 안 드는 이유가, 기존 프로젝트 때문인가?"

**AI**: ① 이식 질문에 = "심는 게 없는 게 설계 알맹이" (외부 관찰자·마커는 이미 있는 문구 선택·L3만 2모드 협조) ② 깊이 질문에 = "기준선이 프로덕션 SaaS라 생기는 눈높이 문제 + 이 과제의 평가축은 결과물 깊이가 아니라 과정 깊이" 프레이밍.

**나**: 프레이밍 수용하되 결론은 반대로 — **"중간 단계로 잡지 말고 여기서 깊게 들어가야 한다. 감지 말고 한 축 더. 트래픽으로 인젝션 감지 같은 느낌? 리서치 돌려볼까"**

**AI (교정)**: 트래픽 관찰은 요청 길목에 서야 함 = 설치형 = 무설치 포지셔닝과 모순. 대신 같은 직관의 실현 가능형 = **페이지에 드러난 침해 흔적의 외부 관찰** (클로킹 비교·스크립트 인벤토리·블랙리스트 등재). 감으로 확정하지 않고 리서치 발사.

**리서치 결과** (`03-보안축-리서치.md` 박제): 추가 가치 있음 — 카테고리 실재(Reflectiz $22M·Sucuri SiteCheck) + 한국 클로킹 도박 스팸 실증 + 무설치 정합. 추천 = **UA 클로킹 비교 + Safe Browsing 등재 체크**, 스크립트 diff는 로드맵만. "하지 말 것" 경계 5개 명시.

## 이 세션의 의미 (회고 재료)

- 사람이 방향(보안 축)을 던지고, AI가 기술적 모순(트래픽=설치형)을 교정하고, 리서치로 검증한 뒤, 스코프 결정은 다시 사람에게 — 역할 분담이 정확히 작동한 왕복
- "깊이 부족" 체감의 해부: 결과물 깊이(폭)와 과정 깊이(검증 밀도)를 분리 → 사토시 결정 = 결과물 쪽도 한 축 보강
