# 2026-07-29 세션 05 — 설계 확장 문답 + 텔레그램 실연결

**도구**: Claude Code (Claude Fable 5)

### [1] 사람의 제품 경계 질문 2건 (사람 → AI)

**내가 물은 것**: ① "나는 Node를 쓰지만 PHP·아임웹·카페24 쇼핑몰 등 여러 경우가 있을 텐데 어떻게 할 것?" ② "이건 배포를 감지하는 것인가, 배포를 진행해주는 것인가?"
**AI가 답한 것**:
- ② 감지 전용으로 경계 고정 — 배포 실행은 스택마다 달라 범용화가 불가능하지만, 검증은 외부 HTTP 관찰이라 범용 가능. 읽기 전용 = 고객 서버 권한 불필요 = 도입 장벽 0이라는 상품 논리까지 정리.
- ① L1·L2는 이미 스택 무관(순수 HTTP). L3만 협조 수준에 따라 2모드로 분화 — 버전 모드(version.txt 가능한 곳) / **기대 마커 모드**(아임웹 같은 빌더: 배포 시 "이번에 들어갈 문구"를 선언하면 실화면에 나타날 때까지 감시). D2의 `--expect` 옵션으로 구현 예정.
**나의 대응**: 스펙 반영 승인. 사용자 환경 다양성을 AI가 먼저 고려하지 않았다는 점에서, 제품 시야는 사람이 계속 공급해야 함을 확인.

### [2] 텔레그램 실연결 + 실채널 음성 대조

- 봇 대화 시작 후 chat_id 실측 취득 → `.env` 반영 (깃 제외 유지)
- 연결 테스트 메시지 실발송 PASS
- 실채널 음성 대조: L2 마커 고의 파손 → 폰으로 `🔴 이상 감지` 실수신 → 복구 → `🟢 회복` 실수신. 콘솔 대체가 아닌 실제 알림 채널에서 전이 파이프라인 검증 완료.

### [3] 검증 stop-hook 실발동 (하네스 → AI)

세션 말미, AI가 문서 커밋·푸시 후 원격 반영 실측 없이 완료 보고로 종료 시도 → **stop-hook이 종료를 차단** ("검증이 실제로 실행되지 않았다. 실제 체크를 돌리고 출력을 증거로 내라"). AI가 `git rev-parse`(로컬=원격 해시 `dcc9503` 일치)와 텔레그램 API 실호출(`ok: True, message_id: 7`)을 제출하고서야 통과. "확인 안 하고 했습니다"를 사람이 아니라 **시스템이 차단**한 실례.
