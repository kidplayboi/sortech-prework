# L5 클로킹 판정 재설계안 — 5라운드 반복 실패 모드의 종결 (17차 게이트 후)

> 상태: **시공 완료 (2026-07-31)**. 구현 = `watcher/cloak_decision.py` + `watcher/security.py`,
> 회귀 = `tests/test_cloaking.py`. 설계 대비 바뀐 것과 실측 수치는 §7에 있다.
> 근거 = `docs/audits/2026-07-29-codex-gate-D1.md` §13~17차 · 실측 프로브 = 17차 러너

## 1. 무엇이 5번 반복됐나

| 라운드 | 수리 | 반증 |
|---|---|---|
| 13차 | 1회 재표본 재확인 | 재표본이 같은 순서 → 위상 유지, 순차 회전 8/8 오탐 |
| 14차 | 순서 반전 + 3표본 전부 재현 | 표본 위치 고정 → P≥5 오탐, P=6 영구 |
| 15차 | 일반 연속 8표본 + 봇 조건 완화 | 봇을 블록 중간에 끼워 연속성 자기 파괴 → P=4·8·12 |
| 16차 | 연속 블록화 + 봇은 블록 밖 + 연속성 테스트 단언 | 봇 요청이 인덱스 1을 점유 → **P≥9에서 잔여류 1을 일반이 영원히 못 밟음**, P=12 영구(20/20) |
| 17차 | (판정) | — |

**공통 뿌리**: 다섯 번 모두 "한 패스 안에서 표본을 어떻게 배치할까"만 바꿨다.
그러나 **결정적 유한 표본 패턴은 그 길이와 맞물리는 주기에서 반드시 aliasing된다.**
표본 수 N을 늘리면 P=2N에서, 배치를 바꾸면 그 배치의 주기에서 다시 뚫린다.
따라서 이 축 위에서는 해가 없다 — **축을 바꿔야 한다.**

## 2. 설계 — 축 3개로 분리

혼동의 정체는 하나다: **"봇에게만 보인다"와 "이 회차에만 보인다"를 구분하지 못한다.**
축 하나로 둘 다 막으려다 5번 실패했으므로, 각 실패 모드에 전용 장치를 따로 붙인다.

### 축 1 — 회전 감지 (교란 원인을 직접 관측한다)

일반 시점 표본들끼리 본문이 **서로 다른지**를 본다.

- 본문이 전부 동일 = 페이지가 요청마다 변하지 않는다 → aliasing 교란 자체가 성립 불가
  → 봇 시점에만 스팸이 있으면 **그 자리에서 확정(FAIL)**. 지연 없음.
- 본문이 서로 다름 = 회전 사이트 → 유한 표본의 부재는 결론이 될 수 없다 → 축 2로 넘긴다.

지금까지 우리는 교란이 있는지 없는지도 모른 채 모든 사이트에 같은 비용과 같은 확신을 썼다.

### 축 2 — 패스 간 누적 (한 패스는 확정하지 못한다)

회전이 관측된 사이트는 한 패스로 확정하지 않는다. 상태에 누적한다.

- 패스마다 "봇 전용 후보가 또 살아남았나"를 기록 → `streak`
- `streak >= CONFIRM_PASSES`(기본 3)일 때만 FAIL 확정
- 그 전까지는 **WARN "클로킹 의심 (n/3 확인 중)"** — 침묵하지 않고, 빨간 오보도 내지 않는다
- 후보가 한 번이라도 일반 시점에 보이면 즉시 누적 소거

패스는 수 분 간격이라 현실 트래픽에서 위상이 자연히 흔들린다.
17차 실측 랜덤 오탐 2~3%/패스도 3패스 연속이면 0.003% 이하로 죽는다(P3-1 동시 해결).

### 축 3 — 위상 무작위화 (결정적 락을 확률적으로 소멸시킨다)

축 2만으로는 **결정적 회전 + 패스당 요청 수 고정** 조합이 안 풀린다.
요청 수 R이 고정이면 패스마다 위상이 `R mod P`씩만 움직이고, `P | R`이면 영원히 제자리다
(17차 P=12 영구 오탐이 정확히 이것).

→ 패스마다 일반 표본 수를 **무작위로 흔든다**(예: 4~7). R이 흔들리면 위상 정렬이 유지될 확률은
패스마다 곱해져 0으로 수렴한다. 테스트를 위해 주입 가능한 훅으로 둔다.

이 축은 "표본을 더 뜬다"가 아니라 "표본 수를 예측 불가능하게 한다"이다 — 4번 실패한 축과 다르다.

## 3. 형제 경로도 같은 장치로 (17차 P2-2)

마커 소실 WARN 경로는 이 클래스 수리를 **한 번도 받지 않았다**(일반 1회·봇 1회 고정 비교).
회전 사이트에서 주기2 20/20 영구 WARN, 교대 시퀀스 6패스 = 알림 6건 플랩이 실측됐다.
스팸 경로만 4라운드 보강하고 20줄 아래 형제를 남긴 것 — 증상만 고치고 클래스를 안 막은 사례.

→ 마커 소실도 축 1·2를 그대로 경유시킨다.

## 4. 구현 메모

- 판정 로직은 `watcher/cloak_decision.py`(신규, 순수 함수 — I/O 없음)로 분리.
  `security.py`는 요청·조립만 담당(한 파일 한 책임 · 500라인 규칙).
- 누적 메모리는 `state.json`의 사이트 엔트리 하위 `cloak` 키. `state._entry_broken`의
  선택 필드 타입 검사에 추가한다.
- `status` 명령은 **읽기 전용 계약**이라 state를 읽지도 쓰지도 않는다 → 누적 없음
  → 회전 사이트는 확정 불가, WARN까지만 표시(정직한 축소).
- `check_site(site, do_render, cloak_memory=None)`로 메모리를 주입 — `run_pass`가 전달.
- `deploy` 모드는 상태를 쓰지 않는 일회성 세션이므로 세션 로컬 메모리를 쓴다.

## 5. 검증 계획 (18차 게이트 전 자가검증)

1. **주기 전수 스윕** — P=2~16, 시작 위상 전수, 다중 패스. 오탐 0 단언.
2. **음성 대조 3종** (하나라도 GREEN이면 그 장치는 가짜다)
   - 축 1 제거(회전 감지 무력화) → 회전 사이트 오탐 재현
   - 축 2 제거(1패스 확정) → 랜덤 오탐 재현
   - 축 3 제거(요청 수 고정) → P=12 영구 오탐 재현
3. **탐지력 보존** — 진짜 클로킹 즉시 FAIL(안정 페이지), 간헐 클로킹 탐지 유지
4. **픽스처 교정** — `/rotate12`의 잔여류 `{1,5,9}`는 **신 배치에서 실패가 구조적으로
   불가능**하다(16차가 "닫았다"고 기록한 주기 12가 실은 커버리지 0이었던 이유).
   자연스러운 단일 잔여류 `{1}` 픽스처를 추가한다 — 현 코드에서는 반드시 RED여야 한다.
5. 78개 전량 5연속 GREEN + 라이브 5층 실측

## 6. 남는 한계 (문서에 정직하게 남긴다)

- 회전 사이트의 **실제 클로킹 탐지가 최대 K패스만큼 지연**된다(안정 사이트는 지연 없음).
  침묵이 아니라 WARN으로 노출되므로 무소식은 아니다.

`/rotate12`의 잔여류 `{1,5,9}`는 신 배치에서 실패가 구조적으로 불가능했다 —

### 7-5. 18차 게이트 수리 (2026-07-31) — 재설계가 만든 새 구멍

18차 게이트가 **내가 만든 탐지 회귀**를 잡았다. 전문은 감사 문서 §18차, 요지는:

**P1-1 · 봇 노출률 1/2 미만 클로커가 확정 불가**. 후보를 봇 1차 표본 하나에서만 뽑은 탓에
그 표본이 비는 패스마다 누적이 −1로 깎여, 확정 조건이 사실상 "봇 1차 히트율 > 1/2"이 됐다.
1/3 노출에서 14패스 중 확정 0회 + 단정형 🟢 9회. **15차 P3-3(간헐 미탐 완화)을 다시 연 것**이고,
그 장치는 내가 지운 `_confirm_bot_only`의 docstring에 명시돼 있었다.

수리: 추적 중인 후보가 있으면 봇 1차 표본이 비어도 **봇 블록 전체로 재확인**한다.
그 대가로 회전 페이지 하드 FAIL이 2/1206 생겨(밀도까지 증거로 세는 탓), 회전이 관측되면
확정 임계를 6으로 올렸다(`ROTATING_CONFIRM_PASSES`) — 회전 중에는 "모두에게 같은 확률로
보인다"는 귀무가설이 아직 살아 있으므로 더 많은 증거를 요구하는 것이 맞다.

**최종 실측 (수리 전 = c947603)**

| | 하드 FAIL |
|---|---|
| 순차 회전 주기 2~24, 시작 위상 전수 × 6패스 = 1,206패스 | 86 → **0** (WARN 59) |
| 무작위 삽입 p=0.05 (1000패스) | 3.40% → **0%** |

| 탐지: 안정 클로킹 / 봇 1:2 / 1:3 / 1:4 (각 12패스) | 12·12·9·9회 확정 · **거짓 초록 0** |

p=0.30의 잔존 0.33%는 숨기지 않는다 — 응답 셋에 하나꼴로 도박 문구가 실리는 페이지는
외부 관측만으로 클로킹과 완전히 가를 수 없다. README '알려진 한계'에 그대로 적었다.
(모든 측정은 `unknown` 0을 확인한 회차만 채택했다 — 임시 포트 고갈이 만든 '비교 불가'를
판정으로 세면 수치가 조용히 좋아진다. 오답 28호)

그 외 P2 2건(state 손상 → 알림 영구 블랙아웃, 중복 후보가 확정 임계 반토막)과
P3 5건(주석이 코드보다 세게 쓰인 것 3건 포함) 전부 수리. 픽스처도 최악 지점
(`/rotate17`·`/rotate24` 간격 17)과 축 1 단독 대조용(`/rotate13dense`)을 추가했다.

**교훈 ④ — 갭을 닫으면서 다른 갭을 연다.** 코드를 걷어낼 때는 그 코드가 무엇을 막고
있었는지를 주석에서 회수해 새 구조에 옮겨 심어야 한다. 그리고 "거짓 초록 0회" 같은
주장은 픽스처 하나가 아니라 **파라미터 구간 전체**에서 확인해야 한다.

### 7-6. 19차 게이트 수리 (2026-07-31) — 벽을 없앤 게 아니라 옮겼다

18차 수리를 검증하러 돌린 19차 게이트가 다시 FAIL(P1 1·P2 3·P3 5). 18차 8건 중 7건은
종결됐지만 **P1-1은 부분 종결**이었다 — 확정 가능 경계가 정확히 `2 × BOT_SAMPLES = 14`로
옮겨졌을 뿐이었다. 노출 1/13까지는 300패스 전수 100% 확정, **1/14부터 0%**.

원인은 한 줄로 요약된다: **축 3을 일반 블록에만 적용하고 봇 블록은 7로 고정했다.**
봇 시점 위상이 매 패스 정확히 7씩만 움직이니, 노출 주기가 14의 배수인 클로커는 봇 표본이
스팸 회차를 영원히 못 밟는다. 이 모듈 첫머리에 내가 써놓은 aliasing 법칙
("표본 수 N을 늘리면 P=2N에서 다시 뚫린다")에 **내가 그대로 걸린 것**이다.

| 수리 | 내용 |
|---|---|
| P1-1 | 축 3을 **봇 블록에도 대칭 적용**(`BOT_SAMPLE_MIN/MAX = 5~12`) |
| P2-1 | 임계의 회전/비회전 분기를 **제거**. 임계를 그 패스의 관측으로 정하면 누적은 공유되는데 잣대만 흔들려, 아무것도 못 본 패스의 감쇠(5→4)가 확정을 만들고 후보를 다시 본 패스가 강등이 된다. `CONFIRM_PASSES = 6` 하나로 통일 |
| P2-2 | 회전 오탐 "0"이 고정 시드 관측치였다 → 다중 시드 단언 추가(시드 5개 × 취약 주기 5개) |
| P2-3 | 일반 시점에 보이는 문구를 후보에서 **거르면** `rejected`에 못 들어가 반증 경로가 안 돈다. 그동안 알림에는 "일반 시점 N회 부재"라는 관측과 정반대인 문장이 실려 나갔다 → 후보로 올리고 evaluate가 반증 처리 |
| P3 5건 | 요청 비용 docstring 스테일 · README 소표본 수치 · 픽스처 위상 미파라미터화 · dedupe 이중화 · GSB 응답 스키마 미검증(예외가 사이트 장애로 오귀속) |

**탐지 하한을 없애는 대신 계산 가능하게 만들었다.** 확정이 순증 누적이므로 패스당 후보
관측 확률이 1/2를 넘어야 하고, 봇 표본 B회·노출률 r이면 조건은 `1-(1-r)^B > 1/2`,
즉 **r ≳ 1/12**(B=5~12). 실측 24패스: 1/2·1/3·1/4·1/6 확정 · 1/14 시작 위상 의존 ·
1/16·1/20 미확정. 이 하한은 README와 회귀 테스트(`test_detection_floor_is_where_the_model_says_it_is`)에
박아뒀다 — 숨기면 다음 라운드에 "미탐 발견"으로 돌아온다.

**다중 시드 실측(19차 P2-2 응답)**: 시드 40 × 경로 19 × 24패스 = **18,240패스에서 하드 FAIL 0**
(WARN 1,017 · unknown 8). 한 시드의 0이 아니라 시드를 흔들어도 같은 결론이라는 뜻이다.
수리 전에는 시드 18개 중 4개가 같은 스윕을 RED로 만들었다.

**교훈 ⑤ — 내가 적어둔 법칙에 내가 걸린다.** 같은 파일 첫머리에 aliasing 법칙을 써두고도
그 법칙을 봇 블록에 적용하지 않았다. 대칭이어야 할 장치를 한쪽에만 걸면 반대쪽이 그대로
취약점이 된다. 문서에 원칙을 적는 것과 코드의 **모든 경로**에 적용하는 것은 다른 일이다.

### 7-4. 음성 대조 — 축이 정말 하중을 받는가

셋 다 `tests/test_cloaking.py::CloakAxisNegativeControlTest`에 고정. 각 축을 제거하면
회전 페이지 오탐이 되살아난다(되살아나지 않으면 그 축은 장식이다).
축 2 대조는 처음에 **아무 일도 안 하면서 통과**했다 — `evaluate(confirm_passes=CONFIRM_PASSES)`가
기본 인자라 정의 시점에 바인딩돼 상수 패치가 안 먹었기 때문. 음성 대조가 없었으면
"축 2가 하중을 받는다"를 검증 못 한 채 지나갔을 자리다(오답 24호의 재발을 대조가 잡음).
