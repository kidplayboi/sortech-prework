## P1 (치명 — 핵심 기능이 조용히 틀림)

| ID | 위치 | 내용 | 출처 |
|----|------|------|------|
| P1-1 | checks.py L2 | charset 없는 `text/html`을 requests가 ISO-8859-1로 디코드 → **한글 마커가 영원히 불일치, 정상 페이지를 FAIL 오탐**. charset 미표기는 국내 호스팅에서 흔함 — 도구 대표 기능이 상시 오탐으로 뒤집힘 | 러너 자체 발견 |
| P1-2 | cli/state | "알림 없음"이라던 `status` 명령이 state를 기록해 **전이를 소비** → 이후 순찰에서 장애 알림 증발 (실측: 장애 중 status 1회 → 이후 2패스 알림 0) | Codex 수용 |
| P1-3 | state | 첫 관측은 무조건 무알림 → **처음부터 죽어 있던 사이트는 영원히 침묵** | Codex 수용 |
| P1-4 | cli/state | state 선기록 후 발송 반환값 폐기 → **전송 실패(순단·429) 1회 = 그 장애 영구 미통보** | Codex 수용 |

P1-2/3/4의 뿌리는 하나 — `status` 필드가 "관측된 상태"와 "통보된 상태"를 겸직. **교정 = notified 분리** (발송 성공 후에만 갱신).

독스트링 "앞 층 죽으면 스킵"이 코드와 불일치 / `no-cache` 무시 과경보·`MAX-AGE` 미인식·초 단위 반올림·단위 미환산 / 캐시 정책 귀속 문구 부정확 / fragment URL에서 캐시 우회 쿼리 소실 / 벽시계 시간·10초 장애를 "1분" 보고 / 죽은 코드(save_sites) / 진단 정보 뭉갬 / `v` 접두 하드코딩 / 항상 exit 0 / `__main__` 가드 없음 / 주기 드리프트·Ctrl+C 트레이스백
