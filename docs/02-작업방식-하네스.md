# 작업 방식 — AI 하네스 구성과 메모리 사용 기록

> 이 과제는 "AI를 얼마나 깊게, 주도적으로 부렸는가"를 평가한다. 그래서 결과물만이 아니라,
> AI를 부리는 **시스템 자체**(하네스)와 그 시스템이 이 과제에서 실제로 발동한 기록을 공개한다.

## 사용 AI 도구 (모델명 포함)

| 도구 | 역할 | 이 과제에서 실제 사용 |
|------|------|----------------------|
| Claude Code (Claude Fable 5) | 주 작업자 — 분석·설계·빌드·검증 | 전 세션 |
| Codex (gpt-5.6, reasoning xhigh 고정) | **교차 리뷰 게이트** — 주 작업자가 짠 코드를 다른 AI가 P1/P2/P3로 적대 리뷰 | D1 코어 머지 전 게이트 (세션 06) |
| insane-search (커뮤니티 수집 파이프라인) + 웹 검색 | 주제 리서치 — 실 판매 데이터·트렌드 수집 | 세션 02 |

한 AI의 산출물을 같은 AI가 검사하면 같은 맹점을 공유한다. 그래서 **작성자(Claude)와 검사자(Codex)를 분리**하고, 검사 결과도 맹목 수용하지 않고 지적별로 수용/기각을 판단한다.

## 상시 가드 (사람이 매번 시키지 않아도 걸려 있는 것)

| 가드 | 무엇을 막나 | 이 과제에서 발동한 실례 |
|------|------------|------------------------|
| **검증 stop-hook** | AI가 실제 검증 명령 실행 없이 "완료했습니다"라고 보고하면 종료를 차단하고 실측을 강제 | 세션 05 말미 실제 발동 — 푸시 후 원격 반영 실측 없이 종료 시도 → 차단됨 → `git rev-parse`(로컬=원격 해시 일치)와 텔레그램 API 실호출(`ok: True`)을 증거로 제출하고서야 통과 |
| **영구 메모리 (작업 규칙)** | 과거 실수에서 추출한 규칙을 세션마다 자동 주입 — 같은 실수 반복 차단 | 아래 표 |

## 이 과제에서 발동한 메모리(작업 규칙) 기록

축적된 작업 규칙 중 이번 과제에서 실제로 적용된 것들. (규칙은 과거 실전 실수에서 만들어진 것으로, 원문에서 무관한 맥락은 제외하고 일반화해 기재)

| 규칙 (메모리) | 유래 | 이 과제에서의 적용 |
|--------------|------|-------------------|
| "확인 안 하고 '했습니다' 금지" | 검증 없는 완료 보고로 인한 사고 재발 방지 | 모든 "완료"에 실측 출력 첨부 (커밋 해시 대조·HTTP 응답·실행 로그) |
| 음성 대조 — 가드를 일부러 깨서 검증 | 정상 케이스만 보면 "안 우는 감지기"를 못 잡음 | 세션 04: L2 마커 고의 파손 → 🔴 발화 확인 → 복구 → 🟢 확인 |
| 실측 후 단정 — 추측으로 설계 단정 금지 | 문서/직감만 믿고 단정했다 틀린 사고 | 세션 04: CDN 캐시 가설이 실측과 다르자 응답 헤더를 떠서 원인 확정 (오답 1호) |
| 시크릿 하드코딩 금지 (.env + 코드에서는 환경변수만) | 토큰 유출 사고 방지 | 텔레그램 토큰 .env 격리, 공개 레포 커밋 검사 |
| 한 파일 = 한 책임, 파일 비대화 금지 | 한 파일에 기능이 쌓여 수정 불가능해진 사고 | watcher를 config/checks/state/notify/cli로 분리 |
| 설계 결정은 착수 전 일괄 질의 (추천안 포함) | 빌드 중간 재설계로 인한 낭비 방지 | 세션 03: 감지 깊이·트리거·형태·타깃 4결정 한 번에 |
| 작업 단위 커밋 + 푸시 후 원격 검증 | 배포 후 미검증 사고 방지 | 매 세션 커밋, 원격 해시 대조 |
| 다른 AI로 교차 게이트 후 머지 | 자기 코드 자기 검사의 맹점 | 세션 06: Codex 게이트 |

## 기록 원칙과의 연결

- 위 가드·메모리 발동 내역은 각 세션 로그(`ai-log/`)에도 해당 시점 기준으로 남긴다
- 세션 로그에는 "적용 메모리/규칙" 항목을 포함한다 (아카이빙 프로토콜 v2)
